Module 7 Theory Supplement: Neural Notation

To describe a basic feedforward neural network mathematically, suppose we have \(p\) features with values labeled \(X_{ij}\) for the \(i\)th observation of variable \(j\) . Let \(a_j^{(0)}\) denote the \(j\)th column of the data matrix \(X\). Note this represents the values of feature \(j\) across all observations. It would be more linear-algebra-y to label this \(x_j\), but the \(a\) notation is more common in neural network descriptions so we’re going with it. The \((0)\) superscript is also common because as we will see below we want to define some shit recursively and it makes the formulas easier to write out.

Let \(m\) be the number of hidden units in our network. For each hidden unit \(h\), we’ll take a weighted linear combination of the data vectors \(a_j^{(0)}\) plus a bias term \(b_h^{(1)}\) and feeds it to a nonlinear function \(\varphi\) (called the activation function) to produce the output of the unit:

\[a_h^{(1)} = \varphi\left( \sum_{j=1}^p w_{hj}^{(1)} a_j^{(0)} + b_h^{(1)}\right )\] The outputs of the hidden units are then fed to the output layer via another weighted linear combination to produce an output \(y\): \[y = g\left( \sum_{h=1}^m w_{1h}^{(2)} a_h^{(1)} + b_1^{(2)}\right )\] The output function \(g\) need not be the same as the activation function for the layers. It depends on the task at hand (see below for additional details).

Using this labeling convention, we can add additional hidden layers defined recursively as \[a_h^{(k)} = \varphi\left( \sum_{j=1}^{m_{k-1}} w_{hj}^{(k)} a_j^{(k-1)} + b_h^{(k)}\right )\] for \(k = 1,2,...\) where \(m_k\) is the number of hidden units in layer \(k\) (with layer 0 denoting the input). In matrix vector form, this can be written nicely as: \[a^{(k)} = \varphi\left( W^{(k)}a^{(k-1)}+ b^{(k)} \right)\]

While nnet uses only a single, wide layer for prediction, torch or other deep learning specific packages allow the incorporation of multiple layers.

Activation and Output Functions

The choice of these depends on the task at hand. For the activation function, two common choices are the logistic function \[\varphi(z) = \frac{1}{1+e^{-z}}\] or the rectified linear unit (ReLu) function \[\varphi(z) = \max(0,z)\] Here is what they both look like:

library(tidyverse)

activation_data = tibble(
  x = seq(-3, 3, length.out = 500)
) %>%
  mutate(
    Sigmoid = 1 / (1 + exp(-x)),
    ReLU = pmax(0, x)
  ) %>%
  pivot_longer(
    cols = c(Sigmoid, ReLU),
    names_to = "activation",
    values_to = "output"
  )

ggplot(activation_data, aes(x = x, y = output, color = activation)) +
  geom_line(linewidth = 1.3) +
  scale_color_manual(
    values = c(
      "Sigmoid" = "#E35205",
      "ReLU" = "#004080"
    )
  ) +
  labs(
    title = "Activation Functions",
    x = "Input (z)",
    y = expression(varphi(z)),
    color = "Activation"
  ) +
  theme_minimal(base_size = 13) +
  theme(
    plot.title = element_text(face = "bold"),
    legend.position = "top",
    panel.grid.minor = element_blank()
  )

Both have a change of behavior or “activation” near 0. For the ReLu, this is an on-off activation while for sigmoid its a probability > 0.5 activation. Sigmoid is the default in nnet while ReLu is used in many modern implementations of neural network packages.

The output function depends on the nature of the problem. For regression problems, \(g\) is usually just the identity function and our output is

\[y = \sum_{h=1}^m w_{1h}^{(2)} a_h^{(1)} + b_1^{(2)}\] (or replace the superscript (2) with however many layers you have + 1). For binary classification problems, \(g\) will usually be the sigmoid function while for multi-class problems, it will usually be the “softmax” function which assigns the following score to class \(k\): \[g(z_k) = \frac{e^{z_k}}{\sum e^{z_j}}\] Note in this last case the output is actually multi-valued: \[y_k = g\left( \sum_{h=1}^m w_{kh}^{(2)} a_h^{(1)} + b_k^{(2)}\right )\] for \(k=1,2,...,K\) where \(K\) is the number of classes. The outputs of \(g\) are the predicted probabilities of being in class \(k\)

Matching nnet output to theory.

As an example of this last type of problem, let’s fit a nnet to the iris dataset with 4 hidden units:

library(nnet)
species_nn = nnet(Species ~ ., data = iris, size = 4,trace=FALSE)

You can view the structure of the network using the n output:

species_nn$n
[1] 4 4 3

The first four means there are four inputs (features), the second four means that there are 4 hidden units, and the 3 means there are three classes in our output (species). The weights and biases taking the input to the hidden classes \(H_1, ..,H_4\) can be extracted as follows:

w_input_to_hidden = matrix(
  species_nn$wts[1:20],
  nrow = 4,
  ncol = 5,
  byrow = TRUE
)
colnames(w_input_to_hidden) = c("Bias", colnames(iris)[1:4])
rownames(w_input_to_hidden) = paste0("H", 1:4)
print(w_input_to_hidden)

w_hidden_to_output = matrix(

colnames(w_hidden_to_output) = c("Bias", paste0("H", 1:4))

Let’s use these to hand calculate the predictions on the first observation and compare the results with predict. First, we define our activation and output functions1:

sigmoid = function(z) {
  1 / (1 + exp(-z))
}

softmax = function(z) {
  exp(z - max(z)) / sum(exp(z - max(z)))
}

Then we compute the hidden layer outputs (note that adding the 1 is for the bias):

input = c(1, as.numeric(iris[1, 1:4]))

hidden = sigmoid(w_input_to_hidden %*% input)

And finally, we feed the hidden to the output:

hidden_with_bias = c(1, hidden)

output = softmax(w_hidden_to_output %*% hidden_with_bias)

output
                    [,1]
setosa      1.000000e+00
versicolor 9.801951e-310
virginica   0.000000e+00

Comparing it with the output of predict:

predict(species_nn, newdata = iris[1, 1:4], type = "raw")
  setosa   versicolor virginica
1      1 9.80195e-310         0

They match!
